## What Was Built

1. **Pydantic models** (`src/models.py`): `FightSegmentSummary` and `DungeonRunAnalysisResponse` under Phase 8 section.

2. **Orchestrator** (`src/tools/dungeon_analysis.py`):
   - `_query_all_fights`: Fetches all fight segments from a report (no fightIDs filter)
   - `_classify_segments`: Separates boss (encounterID > 0) from trash, filters fight id 0
   - `_query_dungeon_damage_table`: Full-range damage aggregation with top-15 ability breakdown
   - `analyze_dungeon_run`: Main orchestrator with parallel WCL queries

3. **MCP registration** (`src/server.py`): Tool registered with full docstring, accepts (report, player, spec, include_casts).

4. **Tests** (`tests/test_dungeon_analysis.py`): 7 tests covering query helpers, classification, aggregate DPS, segments, cast toggling, and model serialization.

## Key Design Decisions

- **Active-time DPS**: Total damage divided by sum of individual fight durations, not wall-clock time. This prevents rest periods between pulls from deflating DPS numbers.
- **Rate-limit optimization**: Default 5-7 queries (fights, masterData, damage table, buffs, combatant info, deaths). Per-segment DPS only when <= 10 segments. Cast events only on explicit opt-in.
- **Reuse existing helpers**: Imports `_query_combatant_info`, `_query_death_events`, `_query_damage_done`, `_process_cast_events`, `_extract_combatant_info` from analyze.py; `_query_master_data`, `_query_buff_table`, `_query_cast_events` from rotation.py.
