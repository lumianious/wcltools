**Step B — Create src/tools/dungeon_analysis.py:**

Module docstring pattern matches existing tools. Comments in Chinese with ASCII separators.

Key functions:
1. `_query_all_fights(client, report_code) -> list[dict]` — Query `report.fights()` WITHOUT fightIDs to get all fights. Return list of `{id, startTime, endTime, kill, encounterID, name}`.

2. `_classify_segments(fights) -> tuple[list[dict], list[dict]]` — Split into bosses (encounterID > 0) and trash (encounterID == 0). Filter out fight id 0 (the "all" aggregate if present).

3. `_query_dungeon_damage_table(client, report_code, start_time, end_time, source_id) -> tuple[float, list[dict]]` — Query `report.table(dataType: DamageDone)` with full time range. Return (total_damage, entries_list). Each entry has {name, total}. Process entries to compute total and top-15 breakdown with percentages.

4. `analyze_dungeon_run(client, report, player, spec, include_casts=False) -> DungeonRunAnalysisResponse` — Orchestrator:
   - Extract report code via `extract_report_code`
   - Query all fights + master data in parallel (asyncio.gather)
   - Find player sourceID via `find_actor_id_ci`
   - Compute time range: first fight startTime, last fight endTime
   - Compute active_time_sec = sum of individual fight durations (NOT wall-clock)
   - Classify segments into boss/trash
   - Query in parallel (Tier 1+2): damage table, buff table, combatant info, death events
   - For each fight segment, query per-segment damage via `_query_damage_done` for the segment's time range (reuse from analyze.py) — OR more efficiently, compute per-segment damage from segment time ranges against the whole-run damage table. Actually, for simplicity and rate-limit efficiency, query per-segment damage in a SINGLE batch: one `_query_damage_done` per segment is expensive. Instead, just record duration and let overall DPS be the aggregate.

   **Rate-limit-optimized approach:**
   - Do NOT query per-segment damage separately (too many queries for 20+ segments)
   - For segments list: set `player_dps = 0.0` and `deaths = 0` initially — the per-segment DPS is a nice-to-have but costs N extra queries
   - Instead, focus on: aggregate damage table (1 query), aggregate buff table (1 query), death events (1 query), combatant info (1 query), all fights (1 query with masterData) = 5 queries total
   - Per-segment deaths: filter death_events by timestamp into each segment's time range (no extra query)
   - Per-segment DPS: query damage per segment ONLY if <= 10 segments (reasonable for M+). Use asyncio.gather for parallel queries. Skip if > 10 segments.

   - If include_casts=True: query cast events across full time range (paginated via _query_cast_events), process with _process_cast_events
   - Build top_issues list: simple heuristic (e.g., high death count, low active_time_pct)
   - Return DungeonRunAnalysisResponse

```python
@mcp.tool()
async def analyze_dungeon_run(
    report: str,
    player: str,
    spec: str,
    include_casts: bool = False,
) -> dict:
    """
    Analyze a player's performance across an entire M+ dungeon run.

    Aggregates damage, deaths, buff uptimes, and optionally cast data
    across all fight segments (bosses + trash) in the report. Returns
    overall DPS (using active fight time, not wall-clock), per-segment
    breakdown, and top improvement areas.

    Accepts a report code or full WCL URL. Default cost: ~5-7 WCL points.
    With include_casts=True: +30-100 points (full cast pagination).

    Args:
        report: WCL report code or full URL
        player: Character name (case-insensitive)
        spec: Class spec slug, e.g. "balance-druid", "frost-death-knight"
        include_casts: Enable full cast analysis (expensive, default false)
    """
    client = _get_wcl_client()
    result = await _analyze_dungeon_run(
        client,
        report=report,
        player=player,
        spec=spec,
        include_casts=include_casts,
    )
    return result.model_dump()
```
